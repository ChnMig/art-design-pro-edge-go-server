# 管理端安全边界

## 身份与管理员语义

1. 平台超级管理员必须同时满足用户 ID 为 1、租户 ID 为 1、用户启用且默认平台租户启用。只满足固定用户 ID 不构成平台权限。
2. 租户管理员由 `SystemRole.IsTenantAdmin` 显式标记。管理接口每次请求都必须从数据库复核角色存在、未软删除、属于当前租户、已启用且管理员标志为真，禁止依赖角色数字 ID。
3. 租户侧角色接口不能设置管理员标志；平台侧角色接口可以设置。角色创建后禁止跨租户迁移，仍有用户的角色不能禁用或删除，管理员角色不能删除。
4. 用户管理接口不能修改平台根用户；根用户只能通过当前用户资料接口修改自己的密码和资料。默认平台租户编码不能修改，且不能禁用或删除。

## 租户开户与授权范围

1. 创建租户必须在单个 PostgreSQL 事务中同时创建租户、默认部门、管理员角色、首个管理员用户、初始菜单范围与按钮权限范围。任一步失败必须整体回滚。
2. 新租户默认不分配平台管理菜单及其后代；平台管理 API 仍由平台超级管理员中间件独立保护。
3. 租户菜单范围、按钮权限范围和角色越权关联清理必须在同一个顶层事务中完成。按钮权限必须属于本次选中的菜单。
4. 权限范围覆盖更新使用物理删除旧行，避免软删除历史行持续累积并与唯一索引冲突。

## 迁移与既有数据

1. 初始化迁移必须逐项幂等补齐默认数据，不能因任意菜单存在就跳过角色、部门或用户。
2. 迁移只自动把默认平台根角色标为管理员，不按角色 ID 猜测其他租户管理员。既有租户若由人工数据建立，平台管理员需明确将对应角色的 `is_tenant_admin` 设为 `true`。
